# 決済端末 の設計

untie が、分析と設計から書き出したもの (自動生成。手で直しても、書き出し直すと消える)。

## 読み方

- **操作** が、このシステムで作る機能の単位。ここに無い操作は、作らない。
- 「ほかのシステム」「帳票」と書いてある操作は、このシステムでは作らない。このシステムの操作の前提 (状態・情報・出来事) を、外で作っているもの。
- **決まっていない** と書いてあることは、勝手に決めない。「まだ決まっていないこと」に挙がっているあいだは、実装を始めない。

## 操作

### 支払を記録する

- 作業: 代金を受け取る (担当: レジ担当・来店客)
- 情報: 現金・支払 (取得・保存)
- 情報: 売上 (取得)
- 前提の状態: 1 日の締めの状態 = 営業中 (これ以外のときは、行えない)
- 起きる出来事: カード・電子マネーで支払われた

## 状態

### 1 日の締めの状態

どの情報の状態かは、**決まっていない**。

| 状態 | この状態にする操作 | この状態が前提の操作 |
| --- | --- | --- |
| 営業中 | 「売上を登録する」(ほかのシステム「POSレジ」) | 「売上を登録する」(ほかのシステム「POSレジ」)、「支払を記録する」、「返品・交換を登録する」(ほかのシステム「POSレジ」)、「現金の実際の額を記録する」(ほかのシステム「POSレジ」) |
| 現金確認済 | 「現金の実際の額を記録する」(ほかのシステム「POSレジ」) | 「日次の売上を出力する」(ほかのシステム「POSレジ」) |
| 突き合わせ済 | 「日次の売上を出力する」(ほかのシステム「POSレジ」) | 「売上を本部へ送る」(ほかのシステム「会計システム」) |
| 報告済 | 「売上を本部へ送る」(ほかのシステム「会計システム」) | 「入金を記録する」(帳票「レジ締め表」) |
| 入金済 | 「入金を記録する」(帳票「レジ締め表」) | 無い |

作られたときの状態: 設計に無い (前提の状態なしに、このグループの状態にする操作が無い)。作る手段を足すなら、どの状態で作るかを、呼び出す側が渡す形にする。

## 情報

- 結びつく情報: 商品・現金・支払・売掛金・損益計算書 (PL)
- 保存する操作: 「売上を登録する」(ほかのシステム「POSレジ」)、「返品・交換を登録する」(ほかのシステム「POSレジ」)、「売上を本部へ送る」(ほかのシステム「会計システム」)
- 取得する操作: 「売上を登録する」(ほかのシステム「POSレジ」)、「支払を記録する」、「返品・交換を登録する」(ほかのシステム「POSレジ」)、「日次の売上を出力する」(ほかのシステム「POSレジ」)、「売掛金を登録する」(ほかのシステム「会計システム」)
- テーブル: 決まっていない

### 現金・支払

- 結びつく情報: 売上
- 区分: 支払方法
- 保存する操作: 「支払を記録する」、「現金の実際の額を記録する」(ほかのシステム「POSレジ」)、「入金を記録する」(帳票「レジ締め表」)

- テーブル: 決まっていない

## 区分

- 支払方法: 現金・クレジットカード・電子マネー

## 出来事

- カード・電子マネーで支払われた: 起こすもの: 「支払を記録する」、不定期: 決済端末から決済の結果が届いたとき。これをきっかけに行う操作: 「売掛金を登録する」(ほかのシステム「会計システム」)
