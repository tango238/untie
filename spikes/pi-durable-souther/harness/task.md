design/design.md は、宿泊施設の「宿泊管理システム」の設計です (業務分析ツール Untie から書き出したもの)。この設計から、予約まわりの操作の HTTP API を app/ に作ってください。

## 作るもの

設計の「操作」のうち、次の 7 つを HTTP で行える API:

- 予約を確定する
- 予約を変更する
- 予約を取り消す
- チェックインを記録する
- 部屋の割り当てを記録する
- 追加料金を登録する
- チェックアウトを記録する

確かめるのに要る最小限の操作 (予約や部屋を用意する・今の状態を見る) も足してください。

## 決まり

- TypeScript。Node 22 で、ビルドせずにそのまま動かす (`node src/server.ts`)。外部のパッケージは、要るものだけにする。
- **業務ルールを、アプリケーションのコードに書き直さない。** 状態の移り変わりと、条件のときの別の結果は、model/pms.wasm (design/sys_pms.sou を Souther でコンパイルしたもの) が答える。TypeScript から呼ぶコードは model/pms.ts にある。使い方は、まずこの 2 つと node_modules の @souther-lang/wasm を読んで確かめること。
- データは、プロセスのメモリに持てばよい (データベースは要らない)。
- 設計のシーケンス図の、ふだんの流れと、すべての分岐 (条件のときにどうなるか) を、テストで確かめる。前提の状態が違う操作・無い予約・入力の誤りも確かめる。
- テストを実行して、すべて通るまで直す。通っていないのに「できた」と言わない。
- 設計で決まっていないこと (条件を何で判断するか、など) は、勝手に決めずに、呼び出す側が渡す値にするか、app/README.md の「決まっていないこと」に書く。

## 終わりに

app/README.md に、動かし方・テストの仕方・API の一覧・決まっていないことを書いてください。最後の答えには、作ったもの・テストの結果 (件数)・気づいた設計の抜けを、短くまとめてください。
