# 宿泊管理システム 予約まわり API

状態の移り変わりと条件の分岐は `model/pms.wasm` (Souther) が答える。`app/` は入出力・保存 (メモリ) だけを行う。

## 動かし方
    node app/src/server.ts (または npm start)          # PORT 環境変数で変更 (既定 3000)
Node 22、ビルド不要。

## テスト
    npm test    (app/test/)
    node --test acceptance/run.test.ts   (受け入れテスト、driver は acceptance/driver.ts)
46 件 (ふだんの流れ、条件の分岐、前提の状態が違う全組み合わせ、無い予約/部屋、入力の誤り)。

## API
本文・応答は JSON。状態が違う → 409、無い予約/部屋 → 404、入力の誤り → 400。
条件のときの別の結果 (待つ等) は 200 で、応答の `結果` に書く (状態は変わらない)。

| メソッド/パス | 内容 |
|---|---|
| POST /reservations `{宿泊客:{…}, 内容?:{…}}` | 予約を登録 (仮予約)。※確かめ用 |
| GET /reservations, GET /reservations/:id | 状態を見る |
| POST /rooms `{id, 状態}` / GET /rooms/:id | 部屋を用意・見る (状態は 清掃待ち/清掃中/準備完了/使用中) |
| POST /reservations/:id/confirm | 予約を確定する |
| POST /reservations/:id/change `{内容:{…}}` | 予約を変更する (内容を上書きマージ) |
| POST /reservations/:id/cancel `{取消料が発生する:bool, 取消料?:整数}` | 予約を取り消す。true のとき 取消料 必須で請求に加える |
| POST /reservations/:id/check-in `{早めのチェックインができる:bool, 宿泊客?:{…}}` | チェックインを記録 |
| POST /reservations/:id/assign-room `{部屋:id, 満室である:bool}` | 部屋の割り当てを記録 |
| POST /reservations/:id/charges `{内容, 金額:整数}` | 追加料金を登録 |
| POST /reservations/:id/check-out | チェックアウトを記録 (割り当て済みの部屋は 清掃待ち に) |

条件 (取消料が発生する・早めのチェックインができる・満室である) は呼び出す側が渡す。

## 決まっていないこと
- 上の 3 条件を何で判断するか (設計に式が無い)。取消料の金額も未定なので呼び出し側が渡す。
- 部屋の割り当て時に、予約がどの状態であるべきか (モデルは部屋の状態しか見ない)。アプリでは確かめていない。部屋と予約の対応・部屋タイプ・満室の判断も未定。
- 部屋が未割り当ての予約のチェックアウト: 部屋の更新を飛ばして予約だけ進める。
- 追加料金の登録は「チェックイン済 → —」で、請求の状態は無い。請求は予約に持たせた。
- 予約の登録 (予約サイト側・満室の分岐)、請求金額の計算、請求書発行、料金プラン (保存する操作が無い)、予約の検索条件は設計で未定のため作っていない。GET で一覧・取得のみ。
- 予約内容・宿泊客の項目、認証。
